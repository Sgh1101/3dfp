# 3DFP — 3D 1인칭 멀티플레이어 브라우저 FPS

Three.js 클라이언트 + Node.js 권위 서버(WebSocket)로 만든 **3D 1인칭 배틀로얄 v0.4** 입니다.
점프·정조준(ADS)·앉기·달리기, 서버 권위 보급품 루팅, 선택형 AI 대전을 지원하며 사람끼리의 멀티플레이도 유지합니다.
브라우저만 있으면 설치 없이 접속하고, `npm install && npm start` 한 번으로 서버와 게임이 같이 뜹니다.

방은 하나의 Node.js 프로세스 안에서 메모리로 관리됩니다. 서버리스 호스팅에서는 WebSocket 연결 시간 제한과 인스턴스 간 방 상태 공유 부재가 있을 수 있어, 장시간 멀티플레이를 위한 전용 단일 서버와 같은 안정성을 보장하지 않습니다.

## 1. 실행 방법

```bash
git clone https://github.com/Sgh1101/3dfp.git
cd 3dfp
npm install
npm start
```

- 접속: <http://localhost:3000>
- 포트 변경: `PORT=8080 npm start`
- 요구 사항: **Node.js 18 이상** (개발/검증은 Node 22에서 진행)

서버 하나가 정적 파일(`public/`)과 WebSocket을 **같은 포트**에서 함께 서비스합니다.
별도 빌드 단계나 번들러는 없습니다.

Three.js는 **저장소에 들어 있는 로컬 번들**(`public/vendor/three/three.module.min.js`, three 0.170.0)을
importmap으로 불러옵니다. CDN에 의존하지 않으므로 오프라인·사내망·CDN 차단 환경에서도 그대로 동작합니다.
번들을 다시 만들 때만:

```bash
npm install                 # devDependency three@0.170.0 설치
npm run vendor:three        # node_modules/three → public/vendor/three 복사
```

### 테스트

```bash
npm run check      # 서버(CJS)·클라이언트(ESM)·스크립트 문법 검사
npm run test:ui    # 정적 UI/온보딩/모바일 레이아웃 무결성(브라우저 없이)
npm test           # 단위 테스트 + E2E 스모크 테스트(실서버 + 다중 클라이언트)
npm run test:soak  # 봇 소크 테스트(여러 라운드를 실제로 돌려 배틀로얄 흐름 검증)
npm run test:browser  # 실제 브라우저(헤드리스 Chrome)로 WebGL·조작·반응형 검증
npm run test:all   # 위 테스트를 한 번에
```

- `test/ui-static.js` — 소스만 읽어 UI 계약을 검사합니다: `index.html`·`main.js`·`style.css` 사이의
  id/선택자 불일치, 온보딩·HUD·오버레이 요소 누락, `env(safe-area-inset-*)`·터치 pointer id,
  importmap 로컬 번들, **외부 CDN 참조 0건**, README/CREDITS 필수 항목.
- `test/unit.js` — 게임 로직만 검사(네트워크 없음): 이동 검증, 히트스캔, 재장전/무기 교체, 존,
  **배틀로얄 라운드 규칙(노리스폰·마지막 생존자 승리·시간 종료·인터미션 부활)**, 점프·헤드샷·보급품 재설정,
  연결/방 한도, 레이트리밋, 백프레셔 판정, **스폰 지점이 커버에서 6m 이상 떨어지는지**.
- `test/smoke.js` — 임시 포트에 서버를 띄워 검증: 정적 자원 MIME, 로컬 three 번들 서빙,
  **API 경로 정확 일치(404)**, 워밍업/라운드 시작, 참여·핑 레이트리밋,
  **전역 연결 상한(`SERVER_FULL`)·방 상한(`TOO_MANY_ROOMS`)**, 이동·사격·재장전,
  **무기 교체 시 재장전 취소**, NaN/속도 위반, 종료 처리.
- `test/soak.js` — 봇 4개가 실제로 참여해 1~3라운드를 돌며 **탈락자가 리스폰하지 않는지**,
  마지막 생존자가 승리하는지, 인터미션 뒤 전원이 부활하는지 확인합니다(약 30~60초).
- `test/browser.js` — 헤드리스 Chrome(CDP)으로 **실제 WebGL 화면**을 띄워 온보딩 → 워밍업 → 라운드 →
  이동·점프·달리기·앉기·조준·루팅, 사격·재장전·무기 교체·힐 → 탈락 → 결과 → 다음 라운드,
  PointerLock 잠금/해제·재고정과 드래그 조준 대체 입력, 모바일 터치(조이스틱·드래그 시점·사격 버튼)를 확인합니다. 봇은 WebSocket 클라이언트로 붙어
  서버 스냅샷으로 결과를 교차 검증합니다.
  ```bash
  node test/browser.js --shots=/tmp/3dfp-shots   # 주요 화면 PNG 저장
  CHROME_PATH=/path/to/chrome node test/browser.js
  ```
  Chrome을 찾지 못하거나 실행할 수 없으면(공유 라이브러리 누락 등) **실패가 아니라 SKIP**으로 끝납니다.
  헤드리스 Chrome은 PointerLock 상태에서 `movementX`를 만들지 않으므로, 시점 회전은 같은 형태의
  이벤트로 핸들러 경로를 검증합니다(실제 OS 입력에서는 그대로 전달됩니다).

### 브라우저 요구사항 / 문제 해결

- **WebGL을 지원하는 최신 브라우저**가 필요합니다(Chrome · Edge · Safari · Firefox). WebGL을 쓸 수 없으면
  화면 상단에 안내 배너가 뜨고 로비는 그대로 사용할 수 있습니다.
- 마우스 고정(PointerLock)을 지원하지 않는 환경(일부 내장 브라우저·iframe·원격 데스크톱)에서는
  자동으로 **드래그 시점 모드**로 전환됩니다: 마우스를 누른 채 드래그해 조준하고, 클릭으로 사격합니다.
  ESC로 고정이 풀리면 **`조준 다시 고정` 버튼**으로 바로 돌아올 수 있습니다.
- 포트가 이미 사용 중이면 `PORT=8080 npm start`처럼 다른 포트를 지정하세요.
- Three.js를 불러오지 못하면 상단에 `게임을 시작하지 못했습니다` 배너가 뜹니다. `public/vendor/three/`가
  그대로 있는지 확인하세요(빌드 단계가 없으므로 별도 번들러는 필요 없습니다).

## 2. 조작법

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 이동 | `W A S D` | 왼쪽 가상 조이스틱 |
| 달리기 | `Shift` | 이동 조이스틱 |
| 점프 | `Space` | `점프` 버튼 |
| 앉기 | `C` 또는 `Ctrl` | `앉기` 버튼 |
| 시점 | 마우스 (클릭으로 PointerLock) | 오른쪽 화면 드래그 |
| 정조준 (ADS) | 우클릭 또는 `V` | `조준` 버튼 |
| 사격 | 마우스 왼쪽 버튼 | `발사` 버튼 |
| 재장전 | `R` | `재장전` 버튼 |
| 무기 교체 | `E` (또는 `1` `2` `3`) | `무기` 버튼 |
| 힐 키트 | `Q` | `힐` 버튼 |
| 보급품 줍기 | `F` | `줍기` 버튼 |
| 마우스 고정 해제 | `ESC` | — |

- PC에서 화면을 클릭하면 마우스가 고정되고, `ESC`로 풀립니다. 다시 클릭하면 **카메라 각도가 튀지 않고** 이어집니다.
- 모바일은 안전 영역(`env(safe-area-inset-*)`)을 반영해 노치·홈바에 HUD가 가리지 않습니다.

### 무기

| 슬롯 | 무기 | 피해 | 연사 | 탄창 | 예비 | 특징 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 라이플 | 24 | 110ms 자동 | 30 | 150 | 기본 주무기, 사거리 140m |
| 2 | 권총 | 32 | 220ms 단발 | 12 | 72 | 정확·가벼움 |
| 3 | 샷건 | 11 × 8펠릿 | 800ms | 6 | 36 | 근거리 42m, 탄퍼짐 큼 |

- 재장전 중에 무기를 바꾸면 **재장전은 즉시 취소**됩니다(이전 무기의 재장전이 새 무기에 얹히지 않음).

### 규칙 — 배틀로얄 (노리스폰)

- 아레나: **160m × 160m**, 서버가 아는 AABB 커버(컨테이너·상자·방벽·기둥) 배치.
- 스폰: 중심에서 60m 링의 8지점, 서로 45m 이상 이격 · **커버에서 6m 이상 떨어진 자리**에서 아레나 중심을 바라보고 시작합니다.
- **라운드 중 사망 = 탈락.** 라운드가 끝날 때까지 리스폰되지 않고(`탈락 · 생존자 관전`) 관전합니다.
  탈락 화면은 화면을 가리지 않아 남은 플레이어를 계속 볼 수 있고, 나를 탈락시킨 상대와 무기, 남은 생존자 수를 보여 줍니다.
  (라운드 진행 중에 입장한 플레이어는 `관전` 안내와 함께 다음 라운드부터 참여합니다.)
- **라운드 종료 조건**
  1. 2명 이상으로 시작한 라운드에서 **생존자가 1명**이 되면 → 그 플레이어가 **마지막 생존자 승리**.
  2. 라운드 시간(3분)이 끝나면 → 남은 생존자 중 **HP가 가장 높은 플레이어** 승리(동률이면 킬 수).
  3. 전멸(0명 생존)이면 무승부.
- **인터미션 8초** 뒤 다음 라운드가 자동 시작하고, 그 전에 **전원이 `준비`를 누르면 즉시** 시작합니다.
  새 라운드에서 전원은 `alive: true`, 만HP, 탄약/힐 키트 풀충전, 새 스폰 위치, **구역 3단계 초기화**로 되살아납니다.
- **혼자면 워밍업**: 방에 1명뿐이면 라운드를 시작하지 않고 `워밍업` 상태로 기다립니다(사격 불가, 이동 가능).
  두 번째 플레이어가 들어오는 순간 라운드가 시작됩니다.
- **진행 중 라운드에 입장**한 플레이어는 그 라운드를 관전하고 **다음 라운드부터** 합류합니다.
- 안전 구역이 **3단계**로 축소(20s 대기 → 40s 축소 등), 구역 밖에서는 초당 12 피해.
  HUD에 `안전 구역 1/3` ~ `최종 구역` 단계와 다음 축소까지 남은 시간이 뜨고, 축소 중에는 색이 주황으로
  바뀌며, 구역 밖에 있으면 상단에 경고가 표시됩니다. 구역 벽(원기둥+바닥 링)은 안·밖 어디서나 보입니다.
- 리스폰 직후 **10초 스폰 보호**(사격하면 즉시 해제) — 라운드 시작 스폰에도 적용됩니다.
- 방: 기본 공개방 `LOBBY0` + 6자리 코드로 생성/참여, 방당 최대 **8명**.

### 보급품과 선택형 AI 대전

- 맵의 보급품에서 무기·탄약·힐 키트를 얻습니다. 획득 가능 여부, 거리, 인벤토리 지급과 라운드 사이 재설정은 서버가 판정합니다.
- 새 방을 만드는 사람이 AI 수, 난이도, 빈자리를 AI로 채울지 선택할 수 있습니다. AI는 사람 플레이어와 함께 참가하며 **사람+AI 합계 최대 8명**입니다.
- AI는 시야선, 엄폐물, 안전 구역, 보급품을 고려합니다. 난이도에 따라 반응 속도와 조준 오차가 달라지며, 벽 너머를 보거나 자동 명중하는 방식은 아닙니다.
- AI 설정은 새 방에 적용됩니다. 기본 공개방에 들어가면 실제 사람과의 멀티플레이를 그대로 할 수 있습니다.

## 3. 서버 보호 (연결·방·레이트리밋·백프레셔)

`server/limits.js`에 모아 두고, 환경 변수로 조정할 수 있습니다.

| 환경 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `MAX_TOTAL_CONNECTIONS` | `128` | 동시 웹소켓 연결 상한. 초과 시 `SERVER_FULL` 후 소켓 종료(4013) |
| `MAX_ROOMS` | `32` | 동시 방 수 상한(기본 공개방 포함). 초과 시 `TOO_MANY_ROOMS` |
| `MAX_BUFFERED_BYTES` | `262144` (256KB) | 소켓 전송 버퍼 상한 |
| `SLOW_SOCKET_STRIKES` | `60` | 버퍼가 계속 차 있을 때 스냅샷을 건너뛴 횟수(20Hz 기준 약 3초) → 소켓 종료(4014) |
| `JOIN_RATE_MAX` | `5` | 참여 요청 허용 횟수 / 10초 (소켓당) |
| `PING_RATE_MAX` | `5` | 핑 허용 횟수 / 1초 (소켓당, 초과분은 응답하지 않음) |

- **느린 소켓 보호**: 20Hz 스냅샷을 방송할 때 `ws.bufferedAmount > MAX_BUFFERED_BYTES`면 그 틱은 건너뛰고,
  계속 막혀 있으면 그 소켓만 끊습니다. 느린 클라이언트 하나가 서버 큐/메모리를 잡아먹지 못합니다.
- **API 경로는 정확 일치**로만 매칭합니다(`/api/map`, `/api/config`, `/api/health`).
  알 수 없는 `/api/*`는 `404 {error:"NOT_FOUND"}`를 돌려줍니다.

## 4. 구조

```
3dfp/
├─ server/
│  ├─ index.js     # HTTP 정적 서비스 + WebSocket + 연결/레이트리밋 + 20Hz 틱 루프 + 하트비트
│  ├─ rooms.js     # 방 생성/참여/정원/방 상한/코드 발급/빈 방 정리
│  ├─ game.js      # 게임 상태·이동 검증·히트스캔·존·배틀로얄 라운드·스냅샷
│  ├─ limits.js    # 전역 한도·레이트리밋·백프레셔 가드
│  └─ map.js       # 아레나/커버 AABB/스폰 정의 (클라이언트와 공유하는 단일 소스)
├─ public/
│  ├─ index.html   # HUD·오버레이·importmap(로컬 three)·모듈 로드 실패 안내
│  ├─ css/style.css
│  ├─ vendor/three/three.module.min.js   # three 0.170.0 로컬 번들(+ LICENSE, VERSION)
│  └─ js/
│     ├─ main.js   # Three.js 씬·입력·보간·HUD·탈락/워밍업 표시
│     ├─ net.js    # WebSocket 래퍼 + RTT
│     └─ audio.js  # Web Audio 절차적 효과음 (음원 파일 0개)
├─ scripts/
│  ├─ check.js          # 문법 검사
│  └─ vendor-three.js   # three 로컬 번들 복사
└─ test/
   ├─ unit.js      # 게임 로직 단위 테스트
   ├─ smoke.js     # 실서버 + 다중 클라이언트 E2E
   ├─ soak.js      # 봇 소크(여러 라운드)
   ├─ ui-static.js # 정적 UI/온보딩/모바일 레이아웃 무결성
   └─ browser.js   # 헤드리스 Chrome 실기 브라우저 테스트(WebGL·조작·반응형)
```

### 권위 서버 원칙

- **이동**: 클라이언트 예측 + 서버 검증. 좌표가 `[-80, 80]` 밖이거나 `NaN`/`Infinity`면 패킷 폐기,
  한 틱 허용 거리(`6.6m/s × dt + 0.07m`)를 넘으면 **되돌리고 보정 패킷**(`corr`)을 보냅니다.
- **점프·사격·피해·루팅·존·라운드**: 전부 서버 계산. 클라이언트가 보낸 피해량/명중이나 보급품 획득 결과는 신뢰하지 않습니다.
- **히트스캔**: 커버 AABB를 먼저 통과시킨 뒤 그보다 가까운 플레이어 AABB만 명중 처리.
- **요청 제한**: 이동 40/초, 사격 25/초, 그 외 액션 15/초 (슬라이딩 윈도) + 위 연결/참여/핑 한도.
- **닉네임**: HTML 태그 제거 + 특수문자 이스케이프 + 16자 제한. 클라이언트도 `textContent`로만 출력.

서버 → 클라이언트

| `t` | 내용 |
| --- | --- |

### 렌더링 / 표현

- 원격 플레이어는 **90ms 지연 보간**(스냅샷 버퍼 사이 선형 보간, yaw는 최단 각도)으로 부드럽게 표시됩니다.
- 원격 플레이어는 캡슐 몸통 + 머리 + 발광 바이저 + 무기 모델로 실루엣을 구분하고, 머리 위에 닉네임표를 답니다.
  무기를 바꾸면 상대 총 모델 길이도 바뀌고, 긴 닉네임은 폭에 맞춰 글자 크기가 줄어듭니다.
- 1인칭 뷰모델은 라이플·권총·샷건이 서로 다른 실루엣으로 그려집니다.
- 존은 반지름을 부드럽게 따라가는 원기둥 + 바닥 링으로 표시되며, 안·밖 어디서나 보입니다(축소 중에는 주황).
- 탈락 오버레이는 화면을 가리지 않아 남은 플레이어를 계속 볼 수 있고, 혼자일 때는 상단에 `워밍업` 배너가 뜹니다.
- 효과음은 Web Audio로 합성(사격·명중·킬·재장전·발소리·점프·루팅·구역 경보)하므로 **누락될 음원 파일이 없습니다.**

### 브라우저 검증 범위 (v0.4)

`npm run test:browser`로 **헤드리스 Chrome**(ANGLE + SwiftShader, `WebGL 2.0`)에서 실제 화면을 띄워 확인했습니다.

- 확인됨: WebGL 초기화·캔버스 렌더링, 온보딩→워밍업→라운드 흐름, 오류 안내·입력 유지,
  2인 라운드 시작(20Hz 스냅샷), 이동·점프·달리기·앉기·ADS·보급품 루팅, 사격·재장전·무기 교체·힐, 봇과의 실제 피해/킬,
  탈락·결과(승자/킬/HP/카운트다운/준비), 준비 버튼으로 즉시 다음 라운드, ESC 후 재고정 버튼,
  모바일 세로/가로 레이아웃과 터치(조이스틱·드래그 시점·발사) 멀티터치, 콘솔 오류 0건.
- 이 환경에서 확인하지 못한 것: 실제 GPU의 화질·프레임레이트, 실제 휴대폰(iOS Safari·안드로이드
  Chrome)에서의 터치 감도와 노치 안전 영역, 사람 둘이 같이 플레이할 때의 체감 밸런스.
  헤드리스 CDP는 PointerLock 상태에서 `movementX`를 만들어 주지 않으므로 마우스 시점 회전은
  같은 형태의 이벤트로 핸들러 경로를 검증했습니다(실제 OS 입력에서는 그대로 전달되는 것을 따로 확인).
